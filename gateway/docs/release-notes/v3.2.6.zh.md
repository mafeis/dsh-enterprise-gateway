## 为什么要做

管理台「客户端插件 → 插件仓库」原来只有一个被动角标：`检查更新` 比对
`dist-tags.latest` 与仓库默认版本，比仓库新就在行内给一个「更新到 v\<latest\>」。
两个口子卡死了运维：

1. **只能拿最新那一版**。想装中间版本（灰度到 0.9.14、回滚到 0.9.13）没有入口，
   只能去终端手敲 npm 包名再想办法传包。
2. **上传入库的插件永远不报更新**。`checkNpmUpdates` 里有一句 `if (!reg) continue`，
   upload 来源的插件在索引里没有 registry 记录，直接被跳过——角标永不出现，
   管理员根本不知道 npm 上出了新版。这就是「检测到新版了但不能选择」的根因。

## 改了什么

- **`core/repo-store.mjs` 新增 `listNpmVersions(name, registry)`**：读 npm 包元数据，
  返回全量版本（semver 降序，最多 80 条），每条带 `publishedAt / size` 和
  `latest / inRepo / isDefault` 三个标记。**只读，不写索引**——要不要落库由管理员决定。
  registry 优先级＝入参 > 索引记录的源 > `registry.npmjs.org`，所以上传入库那批
  插件可以临时指定一个源，把版本一次拉齐。
- **新增 `GET /admin/plugin-repo/npm-versions?name=&registry=`**（requireAdmin）。
  包名非法、源不可达、源上没这个包，一律转 400 并带上可读原因，不把上游状态码原样透出。
- **管理台仓库行内新增「版本检查」按钮 + 弹窗**：npm 源输入框（留空用记录的源）、
  摘要条（`npm 最新 0.9.18 · 仓库默认 0.9.15 · 共 11 个版本 · 源 …`）、版本表格
  （发布时间/大小/状态，已在仓库的置灰禁选），勾选后按从新到旧逐个走既有
  `POST /admin/plugin-repo/npm`（`spec=name@ver`）入库，逐个报错不中断，入库完回读服务端
  刷新默认版本与角标。

## 语义（刻意保持不变）

入库只把包放进企业仓库。**版本号高于当前默认版本时默认版本自动跟随**（与行内
「更新到」同一条路径 `putTarball`），**低于默认版本的仅作为可回滚的历史版本存档，
不会把终端默认版本往回拉**。心跳下发给客户端的 `pluginLatest` 取的就是仓库
`defaultVersion`，所以勾一个旧版存档不会误升级、也不会误降级任何终端。
