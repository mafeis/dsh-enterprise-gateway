# DSH 企业网关 · 核心文档

> 版本 v2.2+（2026-09-10）· 源码即运行代码 · 零 npm 依赖（Node 22.5+ `node:sqlite`）
> 配套文档：《DSH 企业客户端插件 · 核心文档》（本目录同级的插件文档）

---

## 1. 它是什么

企业 LLM 网关：员工端（DSH 终端）→ 企业网关（8899）→ 上游供应商（某上游中转等）。

- **模型名抽象**：员工只见企业模型 id（如 `deepseek`、`qwen`），真实上游映射在网关配置里，换上游员工无感
- **留痕审计**：SQLite 只追加 + 每日 Merkle 锚防篡改
- **DLP**：`sk-…` 密钥硬拦截；银行卡/手机号/身份证脱敏放行
- **思考档位**：统一 off/low/medium/high 四档，代理层双风格注入（GLM `thinking` + OpenAI `reasoning_effort`）

## 2. 架构与文件地图

```
gateway/src/
├── config.mjs    # 配置分层 + 供应商/模型 CRUD + 探针（test/probe/probe-levels/probe-all）
├── auth.mjs      # JWT(HS256 零依赖) + scrypt + 请求鉴权
├── dlp.mjs       # 规则引擎：block(拦截) / mask(脱敏)
├── store.mjs     # SQLite 留痕（只追加）+ 每日 Merkle 锚
├── upstream.mjs  # 上游转发：加权负载 + 失败容灾 + SSE 透传 + 思考参数注入
└── server.mjs    # 路由总装 + 引导管理员

gateway/src/routes/
├── chat.mjs      # /v1/chat/completions（OpenAI 兼容，流式/非流式）
├── admin.mjs     # 管理端点（配置/供应商/模型/用户/探测/计费）
├── plugin.mjs    # /heartbeat /policy/ack（插件心跳）
├── auth-routes.mjs
└── usage.mjs

admin-web/        # 管理台前端（无框架，ES modules）
├── index.html → views/shell.html → views/pages/*.html（@include 链）
└── js/main.mjs → js/pages/*.mjs（硬编码 ?v= 时间戳防缓存）
```

**生产部署**：`C:\dsh-gw\`（`start-gw.cmd` + `boot.mjs` + `gateway.db` + `gateway-config.json` + `jwt-secret`），计划任务 `DSH-Enterprise-Gateway` 登录自启。`boot.mjs` 直接 import 源码目录 `<仓库>/gateway/`——**改源码 = 改运行代码**，改完必须重启计划任务。

**启动/重启**：

```powershell
Restart-Process: Get-Process -Id (Get-NetTCPConnection -LocalPort 8899 -State Listen)[0].OwningProcess | Stop-Process -Force
Start-ScheduledTask -TaskName "DSH-Enterprise-Gateway"
# 重启后必须核对新进程 StartTime（旧进程可能没杀干净）
```

**配置路径链**（重要）：`ENT_GATEWAY_CONFIG`（start-gw.cmd 设为 `C:\dsh-gw\gateway-config.json`）→ 不设则回落 `gateway/data/gateway-config.json`。**webadmin 改的是 ENT 指向的那个文件**，别看错文件。

## 3. 核心机制

### 3.1 供应商与密钥

- Provider = `id + baseUrl + 密钥 + 权重/超时/启停`；模型挂在 Provider 下（`providerId + upstreamModel`），支持容灾 `fallbackProviders`
- 密钥解析优先级（`resolveProviderApiKey`）：**明文 `apiKey` 优先 → 环境变量 `apiKeyEnv` → null**
- `/admin/config` 对密钥脱敏：只回 `hasKey`（布尔）和 `apiKeyDirect`（布尔），**不回密钥原文**

### 3.2 思考参数注入（upstream.mjs `applyThinking`）

员工请求 `reasoning_effort: low|medium|high`（或缺省）→ 网关按模型配置转换后发上游：

- 档位取请求值 → 模型 `defaultThinking` → `'off'`
- `thinking: optional` + 非 off → 双发 `thinking:{type:'enabled'}` + `reasoning_effort:<level>`（GLM/Zhipu 风格 + OpenAI 风格兼容）
- `off` → `thinking:{type:'disabled'}`（仅当 `thinking !== 'none'`）

### 3.3 模型探测体系（admin.mjs + config.mjs）

| 端点 | 作用 | 耗时预期 |
| --- | --- | --- |
| `POST /admin/providers/:pid/test` | 连通测试 + 上游 /models 目录 | ~100ms |
| `POST /admin/providers/:pid/probe-all` | 拉目录 + 并发快速探针（off+high 两档），一次出齐可用性 | 3-30s（含 GLM 难题探针） |
| `POST /admin/providers/:pid/probe-levels` | 单模型逐档探测：off/low/medium/high 每档一条真实请求 | 5-40s |
| `POST /admin/providers/:pid/apply-probe` | 把探测结论应用到企业模型目录（新建/更新 thinkingLevels） | 即时 |
| `POST /admin/providers/:pid/probe` | 单模型单次探针（兼容旧入口） | ~1s |

**探针判定逻辑**（`probeProviderModelLevels`）：

- 每档发真实请求，记录 `accepted`（HTTP 200）/ `thought`（有思考痕迹）/ `ms`
- 思考痕迹字段**三兼容**：`reasoning_content`（DeepSeek/OpenAI 系）/ `reasoning`（GLM 系中转）/ `reasoning_text`
- 400 + 错误文含 reasoning/effort/thinking → 判"参数被拒"；404/503+model → "模型不存在"
- `supportedThinking` = 实测产生思考输出的档位；`supportsThinkingSwitch` = off 档无思考 且 有档位有思考
- 应用到模型目录：`thinkingLevels = ['off', ...实测思考档位]`；全无思考 → `thinking: 'none'` 仅 off

**UI 流程**：供应商卡片「测试」→ 弹窗列上游全部模型（快速判定 + 筛选条：全部/支持思考/问题项）→ 每行「逐档测试」展开四档明细 → 「应用」写入企业模型目录（已导入=更新，未导入=新建）。

### 3.4 心跳契约（/heartbeat）

插件定时 POST `{ profile, env, policyVersion, device? }`；网关按 `sha256(Authorization 头)` 作为 device_hash 落库。
响应：`{ ok, deviceAccepted, modelFingerprint }`——`deviceAccepted=false` 表示网关无该设备快照（客户端下次强制全量上报）；`modelFingerprint` = 企业模型 id 列表的 sha256 前 16 位，客户端据此检测模型变更。

### 3.5 管理台静态资源版本化（static.mjs）

- `composeIndex()`：展开 index.html 的 `@include` 注释，给 `/admin/static/...` 引用追加 `?v=Date.now()`（每次请求变，index 不缓存）
- `versionMjs()`：模块间相对 import 追加 `?v=<文件mtime>`；响应头 `cache-control: no-store`
- **但**：各 .mjs 内部的 import 若**硬编码** `?v=<旧时间戳>`，mtime 变了也不会自动更新——见下第 5 节大坑

## 4. 配置参考（gateway-config.json）

```jsonc
{
  "providers": [{
    "id": "provider-a",
    "name": "provider-a",
    "baseUrl": "https://gw-upstream.example.com/v1",
    "apiKey": "sk-…",              // 明文直存（优先生效）
    "apiKeyEnv": "UPSTREAM_API_KEY", // 备选：环境变量
    "timeoutMs": 120000,
    "weight": 10,
    "enabled": true
  }],
  "models": [{
    "id": "deepseek",              // 员工用的模型名
    "displayName": "DeepSeek V4 旗舰",
    "providerId": "provider-a",
    "upstreamModel": "deepseek-v4-flash",  // 真实上游名
    "thinking": "optional",        // optional | always | none
    "thinkingLevels": ["off","low","medium","high"],
    "defaultThinking": "off",
    "contextWindow": 128000,
    "maxTokens": 32768,
    "inputModes": ["text"],        // 只允许 text/image（透传 DSH 前须过滤 video/audio）
    "enabled": true
  }]
}
```

校验红线（`validateModel`）：`thinkingLevels` 必须是数组且元素 ∈ off/low/medium/high；`defaultThinking` 必须在 `thinkingLevels` 内。

## 5. 踩坑实录（每条都真实付过学费）

### 前端（admin-web）

1. **JS 版本号必须手动联动升级**：所有 `js/**/*.mjs` 内部 import 硬编码 `?v=<时间戳>`。改了任何 mjs，必须全局替换旧时间戳为新值（`?v=yyyyMMddHHmmss`），否则浏览器加载缓存的旧子模块——"改了代码不生效"的头号原因。普通 F5 不够时硬刷新 Ctrl+Shift+R。
2. **弹窗内按钮必须独立事件委托**：探测弹窗（probeModal）在 `#provList` 外，事件冒泡不到 provList 的监听器——曾导致弹窗里"逐档测试/应用"点了完全没反应且无报错。现委托挂在 `#probeBody` 上。
3. **编辑态判断不能用 input.disabled**：ID 输入框编辑态保持可输入（支持改名）。用 `disabled` 判断会永远走"新增"分支 → POST 重复 id → 后端 400"ID 已存在" → 保存永远失败且提示不显眼。**必须用 `dataset.orig` 是否存在判断**。此 bug 曾同时坑了供应商编辑器和模型编辑器（显示名改不了的真凶）。
4. **密钥模式回显字段**：`/admin/config` 返回的是 `apiKeyDirect`（布尔），不是 `apiKey`。写错字段名会导致编辑时模式显示错误 + 保存时误清已存密钥。
5. **保存防误清**：env 模式输入框留空时**不得**清 apiKey（曾把生效中的密钥清空导致全部请求失败）；直存模式留空 = 保持原 key。

### 探针

6. **思考痕迹字段三兼容**：只查 `reasoning_content` 会把 GLM 系（思考放在 `reasoning` 字段）误判为"不支持思考"。
7. **探针题目必须能稳定触发思考**：用 "1+1=?" 这种简单题，GLM 会自主跳过思考（reasoning 字段为空）→ 误判"无思考输出"。必须用逻辑推理题（如说谎者谜题）。**判定结果与题目难度强相关**，不是参数问题。
8. **GLM 恒思考**：`thinking: disabled` 也关不掉（off 档照样出思考）。档位差异体现在延迟（low ~2s vs high ~9s）。
9. **probe-all 耗时**：难题探针下全量探测可达 15-30s，前端等待超时要给足（≥30s）。

### 部署/运维

10. **重启后必须核对进程 StartTime**：按 CommandLine 匹配杀进程可能失败，用 `Get-NetTCPConnection -LocalPort 8899` 拿 PID 杀，再确认新 StartTime。
11. **配置文件有两处**：`C:\dsh-gw\gateway-config.json`（生产，ENT_GATEWAY_CONFIG 指向）vs `gateway/data/gateway-config.json`（开发默认）。排查配置问题先确认改的是哪个。
12. **改前端 JS = 改 mjs 文件 + 全局升 ?v= 版本号**，两者缺一不可；网关不用重启（static.mjs 每次读盘）。
13. **测试一律走 CDP 或 API**：Edge 无头截图不可靠；CDP（`msedge --headless=new --remote-debugging-port=9222` + node WebSocket 发 Runtime.evaluate/Page.reload ignoreCache）可完整模拟登录+点击，是端到端验证的可靠手段。CDP 页面若在网关重启完成前打开，会拿到旧 index——验证前先 Page.reload({ignoreCache:true})。

## 6. 端点速查

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/auth/login` | 登录换 JWT（`{token,user,policy}`） |

| PATCH | `/admin/policy` | 策略热更 |

**排错入口**：`C:\dsh-gw\gateway-stdout.log`（全部请求日志，含探测/编辑/登录记录）。
