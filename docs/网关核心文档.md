# DSH 企业网关 · 核心文档

> 版本 v3.0（2026-09-15）· 一切皆插件（Cordis 内核）· 零 npm 依赖（Node 22.5+ `node:sqlite`）
> 运行入口：`gateway/gateway.mjs` → `src/host.mjs`

---

## 1. 它是什么

企业 LLM 网关：员工端（DSH 终端）→ 企业网关（8899）→ 上游供应商。

- **模型名抽象**：员工只见企业模型 id（如 `deepseek`、`qwen`），真实上游映射在网关配置里，换上游员工无感
- **容灾**：模型级备用供应商（`fallbackProviders`），请求级熔断 60s，主家恢复自动回切
- **状态检测**：每供应商独立探测（间隔/连续失败阈值可配），连续失败自动停用、探测通过自动恢复
- **留痕审计**：SQLite 只追加 + 每日 Merkle 锚防篡改
- **DLP**：`sk-…` 密钥硬拦截；银行卡/手机号/身份证脱敏放行
- **思考档位**：统一 off/low/medium/high 四档，代理层双风格注入（GLM `thinking` + OpenAI `reasoning_effort`）
- **管理台**：壳 + 插件页面，供应商/模型/用户/计费/安全/审计/客户端管控/插件管理一体

```

│   ├── dlp.mjs            # 规则引擎：block(拦截) / mask(脱敏)

│       └── ent-*.web/     #   插件自带管理台页面（index.mjs 导出 {html,load,bind}）
```

**插件清单**（`/admin/plugins` 动态发现，禁用插件 = 页面与 API 一起消失）：
ent-router / ent-config / ent-registry / ent-meta / ent-store / ent-auth / ent-security / ent-upstream / ent-catalog / ent-users / ent-billing / ent-client / ent-audit / ent-console / ent-inspector / ent-notify / ent-design

**管理台页面结构**：壳（`admin-web/`）只管登录、顶栏、侧边栏与 hash 路由；每个插件 `.web/index.mjs` 声明 `admin.nav`（图标/标题/排序），router 按 `/admin/plugins` 清单动态注入导航并懒加载页面模块，页面 section id = `page-<路由id>`。

**启动**：

```powershell
cd gateway
node gateway.mjs            # 前台
# 后台常驻（独立进程，勿用 Start-Job——job 回收会杀掉网关）：
Start-Process cmd '/c node gateway.mjs 1>>data\gateway-stdout.log 2>>data\gateway-stderr.log' -WindowStyle Hidden
```

**配置路径链**（重要）：`ENT_GATEWAY_CONFIG` → 不设则回落 `gateway/data/gateway-config.json`。管理台改的是生效中的那个文件。

## 3. 核心机制

### 3.1 供应商与密钥

- Provider = `id + baseUrl + 密钥 + 权重/超时/启停`；模型挂在 Provider 下（`providerId + upstreamModel`），支持容灾 `fallbackProviders`
- 密钥解析优先级（`resolveProviderApiKey`）：**明文 `apiKey` 优先 → 环境变量 `apiKeyEnv` → null**；`apiKeyEnv` 指向 `data/.env` 中 `ENT_PROV_<名字>_KEY` 风格变量
- `/admin/config` 对密钥脱敏：只回 `hasKey`（布尔）和 `apiKeyDirect`（布尔），**不回密钥原文**

### 3.2 容灾（config.mjs + upstream.mjs）

- 模型 `fallbackProviders` 声明备用供应商链；主家请求失败 → 同请求内即切容灾（员工无感），失败供应商熔断 60s
- 熔断过期自动回主家；模型主家与容灾全部不可用 → 终端侧该模型自动下架
- 转发时上游模型名跟随目标供应商（同名跟随，跨供应商模型名不一致时按配置映射）

### 3.3 状态检测（ent-catalog + probe.mjs）

- 每供应商可配：探测间隔（默认 30s）、连续失败 N 次自动停用、探测通过自动恢复
- 探测 = `GET {baseUrl}/models`（只关心可达 + 密钥有效），统计内存计数器：累计/成功/失败/平均延迟/最近探测时间
- 管理台「状态」弹窗看统计；被管理员手动禁用（enabled=false）的供应商不探测
- 端点：`GET /admin/providers/:pid/probe-stats`

### 3.4 模型探测体系（probe.mjs）

| 端点 | 作用 | 耗时预期 |
| --- | --- | --- |
| `POST /admin/providers/:pid/test` | 连通测试 + 上游 /models 目录 | ~100ms |
| `POST /admin/providers/:pid/probe-all` | 拉目录 + 并发快速探针（off+high 两档），一次出齐可用性 | 3-30s |
| `POST /admin/providers/:pid/probe-levels` | 单模型逐档探测：off/low/medium/high 每档一条真实请求 | 5-40s |
| `POST /admin/providers/:pid/apply-probe` | 把探测结论应用到企业模型目录 | 即时 |
| `POST /admin/providers/:pid/probe` | 单模型单次探针（兼容旧入口） | ~1s |

**探针判定逻辑**（`probeProviderModelLevels`）：

- 每档发真实请求，记录 `accepted`（HTTP 200）/ `thought`（有思考痕迹）/ `ms`
- 思考痕迹字段**三兼容**：`reasoning_content`（DeepSeek/OpenAI 系）/ `reasoning`（GLM 系中转）/ `reasoning_text`
- 400 + 错误文含 reasoning/effort/thinking → 判"参数被拒"；404/503+model → "模型不存在"
- `supportedThinking` = 实测产生思考输出的档位；`supportsThinkingSwitch` = off 档无思考 且 有档位有思考
- 应用到模型目录：`thinkingLevels = ['off', ...实测思考档位]`；全无思考 → `thinking: 'none'` 仅 off
- 多模态实测：图片（真实图问答判定）/ 视频（上游 400 即判不支持），结论持久化在模型 `lastProbe.modalities`

**UI 流程**：供应商卡片「测试」→ 弹窗列上游全部模型（快速判定 + 筛选条）→ 每行「逐档测试」展开四档明细 → 「应用」写入企业模型目录。

### 3.5 思考参数注入（upstream.mjs `applyThinking`）

员工请求 `reasoning_effort: low|medium|high`（或缺省）→ 网关按模型配置转换后发上游：

- 档位取请求值 → 模型 `defaultThinking` → `'off'`
- `thinking: optional` + 非 off → 双发 `thinking:{type:'enabled'}` + `reasoning_effort:<level>`（GLM/Zhipu 风格 + OpenAI 风格兼容）
- `off` → `thinking:{type:'disabled'}`（仅当 `thinking !== 'none'`）

### 3.6 心跳契约（/heartbeat）

插件定时 POST `{ profile, env, policyVersion, device? }`；网关按 `sha256(Authorization 头)` 作为 device_hash 落库。
响应：`{ ok, deviceAccepted, modelFingerprint }`——`deviceAccepted=false` 表示网关无该设备快照；`modelFingerprint` = 企业模型 id 列表的 sha256 前 16 位，客户端据此检测模型变更。

### 3.7 管理台静态资源版本化（static.mjs）

- `composeIndex()`：展开 index.html 的 `@include` 注释，给 `/admin/static/...` 引用追加 `?v=Date.now()`
- `versionMjs()`：模块间相对 import 追加 `?v=<文件mtime>`；响应头 `cache-control: no-store`
- **但**：各 .mjs 内部的 import 若**硬编码** `?v=<旧时间戳>`，mtime 变了也不会自动更新——见第 5 节大坑

## 4. 配置参考（gateway-config.json）

```jsonc
{
  "providers": [{
    "id": "provider-a",
    "name": "provider-a",
    "baseUrl": "https://gw-upstream.example.com/v1",
    "apiKey": "sk-…",              // 明文直存（优先生效）
    "apiKeyEnv": "ENT_PROV_EXAMPLE_KEY", // 备选：环境变量（data/.env）
    "timeoutMs": 120000,
    "weight": 10,
    "enabled": true,
    "probe": { "enabled": true, "intervalSec": 30, "failThreshold": 2 }
  }],
  "models": [{
    "id": "deepseek",              // 员工用的模型名
    "displayName": "DeepSeek V4 旗舰",
    "providerId": "provider-a",
    "upstreamModel": "deepseek-v4-flash",  // 真实上游名
    "fallbackProviders": ["provider-b"],   // 容灾链（按序）
    "thinking": "optional",        // optional | always | none
    "thinkingLevels": ["off","low","medium","high"],
    "defaultThinking": "off",
    "contextWindow": 128000,
    "maxTokens": 32768,
    "inputModes": ["text","image"], // text/image（video 由探针实测判定）
    "pricePer1MIn": 2, "pricePer1MOut": 8, "pricePer1MCacheIn": 0.04,
    "lastProbe": { /* 逐档/多模态探测结论持久化 */ },
    "enabled": true
  }]
}
```

校验红线（`validateModel`）：`thinkingLevels` 必须是数组且元素 ∈ off/low/medium/high；`defaultThinking` 必须在 `thinkingLevels` 内。
密钥环境变量：`data/.env` 一行一个 `ENT_PROV_<名字>_KEY=sk-xxx`（.env 与 gateway.db 均不入库）。

## 5. 踩坑实录（每条都真实付过学费）

### 前端（admin-web）

1. **JS 版本号必须手动联动升级**：所有 `js/**/*.mjs` 内部 import 硬编码 `?v=<时间戳>`。改了任何 mjs，必须全局替换旧时间戳为新值，否则浏览器加载缓存的旧子模块——"改了代码不生效"的头号原因。
2. **弹窗内按钮必须独立事件委托**：探测弹窗在 `#provList` 外，事件冒泡不到——曾导致弹窗里"逐档测试/应用"点了没反应且无报错。现委托挂在 `#probeBody` 上。
3. **编辑态判断不能用 input.disabled**：用 `dataset.orig` 是否存在判断；用 `disabled` 判断会永远走"新增"分支 → POST 重复 id → 保存失败。
4. **密钥模式回显字段**：`/admin/config` 返回的是 `apiKeyDirect`（布尔），不是 `apiKey`。
5. **保存防误清**：env 模式输入框留空时**不得**清 apiKey；直存模式留空 = 保持原 key。
6. **按钮文案回滚**：异步按钮点击后改文案，必须在 `finally` 里恢复 `origText`，否则请求失败按钮文字永久卡在"测试中…"。

### 探针

7. **思考痕迹字段三兼容**：只查 `reasoning_content` 会把 GLM 系误判为"不支持思考"。
8. **探针题目必须能稳定触发思考**：简单题 GLM 自主跳过思考 → 误判。必须用逻辑推理题。判定结果与题目难度强相关。
9. **GLM 恒思考**：`thinking: disabled` 也关不掉；档位差异体现在延迟。
10. **probe-all 耗时**：全量探测可达 15-30s，前端等待超时要给足（≥30s）。

### 部署/运维

11. **重启后必须核对进程 StartTime**：用 `Get-NetTCPConnection -LocalPort 8899` 拿 PID 杀，再确认新 StartTime。
12. **后台常驻勿用 Start-Job**：PowerShell job 会话回收会杀掉网关子进程。用独立 `Start-Process cmd '/c node gateway.mjs …'`。
13. **配置文件确认生效路径**：`ENT_GATEWAY_CONFIG` 指向的 vs `gateway/data/` 默认的，排查先确认改的是哪个。
14. **测试一律走 CDP 或 API**：无头截图不可靠；CDP（`--headless=new --remote-debugging-port=9222` + node WebSocket）可完整模拟登录+点击。注意无头新 profile 的 localStorage 与启动链：main.mjs 启动链可能不触发装配，需显式 `import router.mjs` 后 `navigate()`。
15. **改前端 JS = 改 mjs 文件 + 全局升 ?v= 版本号**，缺一不可；网关不用重启（static.mjs 每次读盘）。

| PATCH | `/admin/policy` | 策略热更 |
